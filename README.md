# НарядAI

Прототип системы для выдачи и контроля нарядов на горно-обогатительном предприятии.

## Быстрый запуск

### Двойной клик в Windows

1. Откройте папку проекта в проводнике.
2. Дважды кликните по файлу `start_naryadai.bat`.
3. Приложение запустит сервер и откроет страницу в браузере.

> Скрипт запускает сервер через uvicorn с WebSocket backend `websockets-sansio`, чтобы live-обновления работали стабильно.

## Установка на Android

Приложение можно установить как PWA через Chrome, без публикации в Play Store:

1. Разместите сервер по адресу с HTTPS и откройте его в Chrome на телефоне.
2. В меню Chrome выберите «Установить приложение» или «Добавить на главный экран».

Адрес `localhost` на телефоне указывает на сам телефон, а не на компьютер. Для сетевого тестирования приложение должно быть доступно телефону по HTTPS. Офлайн-режим сохраняет только оболочку приложения; запросы и данные нарядов требуют соединения с сервером.

## Постоянное размещение

Для production задайте переменные окружения в настройках хостинга, не записывайте секреты в исходный код:

- `APP_ENV=production` включает Secure-cookie и production-проверки;
- `DATABASE_PATH` должен указывать на SQLite-файл в постоянном диске/volume, который переживает перезапуск сервера;
- `BOOTSTRAP_ADMIN_USERNAME` и `BOOTSTRAP_ADMIN_PIN` создают первого администратора; PIN/пароль должен быть не короче 12 символов.

В production демо-пользователи и синтетическая история не создаются. Запуск на базе с демо-PIN или сгенерированной историей блокируется. Для MVP используйте отдельную чистую базу, HTTPS и регулярные резервные копии. SQLite рассчитана здесь на один экземпляр приложения; перед запуском нескольких экземпляров потребуется PostgreSQL.

Стартовые справочники материалов, неисправностей и 8 типовых инструментов создаются и в production. Администратор может добавлять ресурсы через панель; код, название и единица измерения используются для нормализации обучающих данных.

Подготовлен запуск через Docker Compose и Caddy:

1. На VPS установите Docker Compose, привяжите DNS A-запись домена к IPv4 VPS и откройте входящие порты 80 и 443.
2. Создайте `.env` на сервере из `.env.example`; укажите реальный домен, имя первого администратора и уникальный секрет длиной не менее 12 символов. Не добавляйте `.env` в Git.
3. В папке приложения выполните `docker compose up -d --build`.
4. Откройте `https://<ваш-домен>` и войдите bootstrap-администратором. Создайте мастеров и исполнителей на странице администратора.

Контейнер хранит SQLite в постоянном volume `app_data`; сертификаты Caddy также сохраняются в volumes. Этот репозиторий подготовлен к развёртыванию, но сам VPS и домен ещё не настроены.

### Через терминал

1. Откройте терминал VS Code в папке проекта.
2. Активируйте окружение:

```powershell
cd D:\AI-naryad
.\.venv\Scripts\Activate.ps1
```

3. Запустите сервер:

```powershell
uvicorn app:app --host 0.0.0.0 --port 8000 --ws websockets-sansio
```

4. Откройте сайт:

```text
http://localhost:8000
```

## ИИ и дедлайны

Текущая оценка не является обученной моделью: без ключа используются фиксированные правила, а при наличии `ANTHROPIC_API_KEY` — отдельный запрос к Anthropic API. Ни один режим не обучается на базе SQLite.

- если переменная `ANTHROPIC_API_KEY` не задана, система автоматически работает в fallback-режиме;
- проверка учитывает приоритет, статус, дедлайн и повторяемость дефекта;
- итог по наряду доступен через `GET /api/ai/check/{id}` и общий обзор через `GET /api/ai/overview`;
- при завершении работы или закрытии наряда система сохраняет `ai_verdict` и `ai_score` в БД.

Демо-история генерируется приложением и не подходит для обучения или оценки качества модели. Для прогноза длительности и ресурсов нужно собирать фактические даты начала/завершения, размер бригады, материалы и инструменты.

Подготовленные записи можно выгрузить через `GET /api/training/dataset` или кнопку в панели администратора. В CSV включаются только наряды с корректными датами старта/завершения, плановым/фактическим размером бригады и длительностью не менее одной минуты; это исключает случайные/тестовые клики. Длительность считается автоматически, ресурсы остаются кодированными позициями. Имена сотрудников, комментарии и описания в выгрузку не включаются. Если фактических завершённых нарядов ещё нет, CSV содержит только заголовок.

Пример для продакшена:

```powershell
$env:ANTHROPIC_API_KEY = "your_key_here"
$env:ANTHROPIC_MODEL = "claude-3-5-sonnet-20241022"
```

## Дорожная карта MVP

1. **Сбор план/факт данных.** Мастер задаёт план бригады и позиции материалов/инструментов с количеством и единицей; исполнитель при завершении фиксирует фактические значения или явно отмечает отсутствие расхода. Ресурсные позиции сохраняются отдельно в `work_order_resource_items`; начало и завершение работ записываются отдельно.
2. **Безопасный постоянный запуск.** Серверная авторизация и проверка прав добавлены. Развернуть подготовленный Docker Compose/Caddy на VPS с HTTPS и резервным копированием базы; временные туннели для этого не подходят.
3. **Полевой сбор.** Накопить реальные завершённые наряды с единицами измерения, кодом неисправности и одинаковыми правилами заполнения. Синтетическую демо-историю исключать.
4. **Первый прогноз.** Обучить baseline-модели длительности и потребности в ресурсах, сравнить их с простым правилом на отложенных по времени нарядах и показывать прогноз вместе с уверенностью и планом мастера.
5. **Android-пилот.** Установить PWA через HTTPS-домен, проверить сценарии мастера и исполнителя на телефонах; исправлять UX по наблюдениям смены.
